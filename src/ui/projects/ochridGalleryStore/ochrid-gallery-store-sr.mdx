# Охридска Галерија Веб-продавница

### Веб-продавница за фикционалну галерију. Садржи функционалност наручивања икона и аутентикацију корисника.

<HeroImage image={OchridGalleryStoreImg} title="Ochrid Gallery E-commerce" />

Охридска Галерија је веб-продавница која омогућава својим корисницима да разгледају и поручују иконе. Вебсајт покреће **Next.js** који пружа брзо почетно учитавање и рендеровање на серверу. Стилизован је преко **Tailwind**-а и могуће га је користити на уређајима разних величина захваљујући прилагодљивом дизајну. Подаци из апликације су сачувани у **Supabase**-овој бази података. Сајт је хостован на **Vercel**-у.

За овај пројекат користио сам и ручни и аутоматски приступ тестирању. Документовао сам тестове у табели путем Google Docs-а, где сам структурисао сваки случај користећи _Given/When/Then_ метод. Што се тиче ручног тестирања, радио сам базичне тестове попут испробавања
"срећне путање" у процесу наручивања, тестирање граничних случајева као што је попуњавање формулара чудним подацима, и тестирање "несрећних путања".

<br />

Након што сам завршио са ручним тестирањем апликације, одлучио сам да интегришем аутоматизацију тестова путем Playwright-а и Vitest-а. Користио сам Playwright за визуелно, интеграционо и **E2E** (End to End) тестирање. Да бих тестирао приступачност, користио сам axe-core библиотеку, која ми је помогла да нађем неке проблеме које сам превидео (попут линка који је био угнежђен у дугмету). За _unit testing_ изабрао сам Vitest уместо Jest-а јер ми је други део овог пројекта — <a href="https://danijelmaksic.vercel.app/ochrid-gallery-cms" target="\_blank" style={{textDecoration: "underline"}} rel="noopener noreferrer">Ochrid Gallery CMS</a> — на Vite-у. Са Vitest-ом сам тестирао индивидуалне функције да бих видео како реагују на тачне, нетачне и чудне уносе.

Ако тест није прошао, повезао бих га са "Извештаји о грешкама" табелом, где бих забележио грешку са јасним инструкцијама за репродукцију. Током развоја ове апликације, већина грешака је била нађена путем истраживачког ручног тестирања.

<br />

Интегрисао сам све своје тестове у **CI** (Continuous Integration) путем GitHub Actions, тако да би се сви тестови аутоматски покренули кад год бих гурнуо свој локални код на мој удаљени GitHub репозиторијум. На овај начин, ако би нова имплементирана функционалност сломила неку другу функционалност (попут наручивања), GitHub Actions би ми показао грешку са детаљима о регресији.
