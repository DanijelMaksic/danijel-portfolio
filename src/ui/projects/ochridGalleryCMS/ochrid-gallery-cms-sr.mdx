# Охридска Галерија CMS

### CMS апликација за фикционалну галерију. Ограничена само за запослене, ова апликација садржи менаџмент инвентара и поруџбина.

<HeroImage image={OchridGalleryCMSImg} title="Охридска Галерија CMS" />

Ово је интерна апликација јавне веб-продавнице "Охридска Галерија". Приступ имају само запослени у галерији. Овај пројекат је _SPA_ коју покреће **React**, пружајући кориснику брзу навигацију.

<br />

Подаци из апликације су сачувани у **Supabase**-овој бази података. Ауторизација и аутентикација корисника су такође изведене користећи Supabase. Сајт је хостован на **Vercel**-у.

За потребе овог пројекта, и ручни и аутоматски приступи тестирању су коришћени. Тестови су документовани у табели путем Google Docs-а, где сам сваки појединачни тест случај структурисао користећи _Given/When/Then_ метод.

<br />

Тестове сам аутоматизовао користећи Playwright и Vitest. Користио сам Playwright за визуелне и интеграционе тестове, ослањајући се на **POM** (Page Object Model) шаблон за олакшавање поновног коришћења тестова. Пошто неки Playwright тестови садрже интеракцију са датабазом, направио сам _fixture_ који не дозвољава да тренутни тест подаци остану у датабази.

<br />

<ArticleImage image={CmsImg11} alt="Табела са тестовима" />

<br />
<br />

За _unit testing_ изабрао сам Vitest уместо Jest-а јер је ова апликација направљена уз Vite. Са Vitest-ом сам тестирао индивидуалне функције да бих видео како реагују на тачне, нетачне и чудне уносе. API сам тестирао путем Playwright-а, потврђујући да основне CRUD операције раде како је предвиђено.

<br />

Интегрисао сам све своје тестове у **CI** (Continuous Integration) путем GitHub
Actions, тако да би се сви тестови аутоматски покренули кад год бих гурнуо свој
локални код на мој удаљени GitHub репозиторијум. На овај начин, ако би нова
имплементирана функционалност сломила неку другу функционалност, GitHub Actions би ми показао грешку са детаљима о регресији.
